**Почему ProcessorCount сравнивают с логическими процессорами, а не с физическими ядрами?**
Потому что операционная система распределяет вычислительные потоки именно по логическим процессорам. Для программы `Environment.ProcessorCount` показывает количество доступных ей потоков (в моем случае 4).

В моем случае физические ядра и логические процессоры совпадают (по 4). Это означает, что у моего процессора (AMD A4-7210) нет технологии Hyper-Threading, которая позволяла бы одному ядру притворяться двумя. Поэтому ОС видит ровно столько же логических процессов, сколько и физических ядер.

## 4. Частота процессора
Во время вычислений частота процессора увеличилась с 1,67 ГГц до 1,82 ГГц. Современные процессоры автоматически повышают частоту при нагрузке (турбо-режим), чтобы быстрее выполнить вычисления, а в состоянии покоя снижают её для экономии энергии.

## Контрольные вопросы
1. **Что показывает Environment.ProcessorCount?**
   Это свойство показывает количество логических процессоров, которые операционная система предоставляет в распоряжение программы.

2. **Чем физическое ядро отличается от логического процессора?**
   Физическое ядро, это реальный вычислительный блок внутри процессора. Логический процессор это то, как ядро видит операционная система. Благодаря технологии Hyper-Threading одно физическое ядро может работать как два логических, но на моем процессоре их количество совпадает.

3. **Почему увеличение количества потоков может увеличить загрузку CPU?**
   Потому что разные потоки могут выполняться одновременно на разных ядрах. Чем больше потоков мы запускаем, тем больше ядер процессора вовлекается в работу.

4. **Почему после некоторого количества потоков загрузка не обязательно продолжает расти?**
   Потому что количество ядер ограничено. Если потоков больше, чем ядер, процессор не может выполнять их все одновременно он тратит время на переключение между ними. Загрузка упирается в максимум.

5. **Почему частота процессора может изменяться во время работы?**
   Процессор динамически меняет частоту в зависимости от нагрузки и температуры. Под нагрузкой он ускоряется, чтобы быстрее справиться с задачами, а без нагрузки замедляется.

## Итоговый вывод
В ходе работы я выяснила, что программа видит количество логических процессоров (4). С помощью Диспетчера задач я увидела, что при запуске одного потока загружается только часть процессора, а при запуске нескольких потоков загрузка значительно возрастает (до 65%). Также я заметила, что под нагрузкой процессор автоматически повышает свою частоту (с 1.67 до 1.82 ГГц) для более быстрой работы. Ядра и логические процессоры могут отличаться (из-за Hyper-Threading), но в моем случае их количество одинаково. Это значит, что мой процессор выполняет потоки без «виртуального» удвоения ядер.
